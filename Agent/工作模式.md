# 1、ReAct

ReAct（Reasoning + Action）：是由Google Brain提出的将推理与行动相结合的革命性范式，核心思想是通过模仿人类：思考 --> 行动 --> 观察 --> 在思考 闭环

## 1.1、ReAct工作模式
1. Tought 思考 ：给予当前和历史信息，LLM进行推理，分析现状，并决定下一步应该做什么
2. Action 行动 ：LLM决定调用那个工具，以及使用那个函数
3. Observation 观察：智能体执行行动（调用工具），并将返回的结果（如搜索结果、代码执行输出）作为观察
4. Loop 循环：智能体将观察到的新信息添加到历史中，然后回到第一步，基于新信息开始新一轮的思考，这个循环会一直运行，直到任务完成

```shell
ReAct模式：Reasoning + Action

           +-------------+
           |  提交任务    |
           +-------------+
                 |
                 V
Thought -> +------------+
           | 思考       |<-----------------------------------------+
           +------------+                                          |
                 |                                                 |
                 V                                                 |
           +--------------------+   是    +----------+        +-------------+
           | 是否需要调用工具 ?  |-------> |  行动     |------> | 观察        |
           +--------------------+         +----------+        +-------------+
                 |                           Action            Observation
               否|
                 V
Final Answer +---------------+
             |  最终答案      |
             +---------------+


   
 
```

# 2、Plan-And-Execute
“计划与执行"架构模式强调AI Agent在面对复杂任务时，能够进行系统性的规划和步骤分解，并按照计划逐步推进任务流程。该模式下AI Agent能够展现出类似人类的前瞻性和策略性思维
```shell

+-------------+      +--------------------------------+     +--------------------------------------+
| 用户请求      |---->| Planner 规划器                 |---->|   Plan 计划清单                       |
| 提出复杂任务  |     | 分析目标\拆解子任务\生成步骤清单  |     |  明确任务目标\拆分子任务\定义执行顺序   |
+--------------+     +--------------------------------+     |  指定工具/输入\设置验收条件            |
                              ^                             +--------------------------^-----------+
                              |                                |                       ^
+------------------+    +--------------------+    +------------V---------+    +------------------+
| Final Response   |<---| Executor 执行器    |     | Execution 执行进度   |    | Replanner         |
| 任务完成、输出结果 |    | 按计划逐步调用工具  |<--- | Step 1--N           |--->| 根据反馈调整计划   |
+------------------+    | 记录结果与状态      |     |                     |    | 处理异常与偏差     |
                        +--------------------+     +---------------------+    +------------------+

Palnner 先把复杂任务拆解 ----> Executor再按步骤逐项完成

1: Planning 规划阶段    2、Execution 执行阶段   3、Feedback 反馈阶段       4、Replan 可选重规划
- 理解任务目标            - 按步骤依次执行         - 检查结果是否满足预期     - 计划错误时局部修正
- 生成完整步骤            - 调用API等工具          - 发现错误或阻塞时上报     - 环境变化时动态调整
- 明确依赖关系            - 记录中间结果与状态      - 触发重试或重规划        - 继续执行剩余步骤
- 可先人工审核计划


核心组件
1、Planner 规划器               2、Executor 执行器                3、Replanner
 - 负责接受任务描述，将复杂         - 负责依序执行计划中的子任务       -在执行失败，信息变化或初始计划
   任务分解为结构化子任务，           并调用外部工具完成具体动作        不准确时，根据当前状态重新生成部分
   通常基于LLM生成步骤、工具          如查询、计算、写入、生成文件      或全部计划，提供容错能力
   输入参数与验收条件


```

# 3、Reflexion即自我反思架构模式
自我反思架构模式允许Agent在完成任务后对自身的输出进行再次审视和评估。在这种模式下，AI Agent不仅能执行任务，还能像人类一样，对自己的工作进行批判性思考

```shell
核心思想： 先做出初稿，再检查是否达标，若失败，则分析原因，写入记忆，重新生成优化版本

+----------+      +-------------+     +-----------------+     Pass           +-----------+
| 用户任务  |---->| 行动者 ACtor |---->| 评估者 Evaluator |----+-------------> | 最终输出  |
+----------+      +-------------+     +-----------------+    |               +----------+
                        ^                                    | Fail
                        |                                    |
                        |                                    V
                        |                           +------------------+       +----------+
                        +---------------------------| 反思者 Reflector  |<---->|  反思记忆  |
                                                    +------------------+       +----------+


Actor生成初稿 ---> Evaluator检查结果 ---> Reflector分析失败原因并写入记忆 ---> 再次生成优化版本
1： 生成 Generate            2、评估 Evaluate               3、反思 Reflect         4、改进 improve
  - 根据任务目标生成初稿         - 判断是否满足质量要求         - 分析失败原因           - 结合反思重新生成
  - 可生成代码、文本、方案       - 可用测试、规则或人工标准      - 总结关键词与改进方向   - 循环迭代直到达标
  - 先得到可评估的第一版         - 输出Pass / Fail             - 形成简洁反思文本       - 设置最大轮数避免过度反思

核心组件
1、行动者 Actor
  - 负责根据任务目标与当前记忆生成输出、可是代码、报告、文案或方案

2、评估者
  - 负责检查结果质量、评估正确性、完整性、效率、可读性等，给出Pass/Fail

3、反思者/记忆 Reflector/Memory
  - 当输出未达标时，分析失败轨迹并沉淀鲸鱼，为下一轮生成提供可执行的改进建议


```

# 4、Multi-Agent即 多Agent协作架构模式
多Agent协作架构模式，突出多个AI Agent之间的合作和协调，在这种模式下，每个AI Agent都可以扮演特定的角色，并与其他AI Agent共同协作以完成复杂任务，通过
代理间的互补和协同作用，提供整体的执行效率和创新能力

```shell
核心工作流阶段

1、任务路由 Task Routing
  - 识别任务类型与目标
  - 判断是否需要多角色协作
  - 选择合适的协作模式

2、专业分工 Specialization
  - 不同Agent负责不同子任务
  - 每个Agent保持清晰职责边界
  - 降低每个Agent的上下文负担

3、协同执行 Collaboration
 - 串行或并行完成子任务
 - 通过协调者或共享状态交换信息
 - 控制依赖关系与执行顺序

4、结果汇总 Aggregation
 - 合并各Agent的结果
 - 解决冲突并统一输出
 - 形成最终答案或交付物

```
