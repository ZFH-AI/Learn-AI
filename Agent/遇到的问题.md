# 1、怎么实现Agent输出过程中的终止操作？同时将已经输出的结果保存？

  - 1、基于 HTTP 流式响应（SSE）—— 检测客户端断开；前端用 fetch + AbortController 断开连接，后端通过检测 request.is_disconnected() 来中断生成

    核心思路：

    - 后端使用 异步生成器 逐步产出 token
    - 在每个 token 产出前检查“是否被中断”（比如客户端断开、收到停止消息）
    - 一旦中断，立刻退出循环，将当前已累积的文本保存到数据库/缓存/会话中
    - 保存的内容可以是一条“半截消息”，后续用户可以继续编辑或重试

```python
import asyncio
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
import json

app = FastAPI()

# 模拟 LLM 异步生成器
async def fake_llm_stream(prompt: str):
    for word in ["你好", "，", "这是", "一个", "长", "回复", "……"]:
        yield word
        await asyncio.sleep(0.3)  # 模拟生成耗时

async def generate_with_interrupt_check(prompt: str, request: Request):
    """可被中断的流式生成，并保存中断结果"""
    accumulated = []
    try:
        async for chunk in fake_llm_stream(prompt):
            # 检查客户端是否断开
            if await request.is_disconnected():
                # 保存已生成内容
                await save_partial_result("".join(accumulated))
                return   # 结束流

            accumulated.append(chunk)
            yield f"data: {json.dumps({'token': chunk})}\n\n"
    finally:
        # 无论正常结束还是断开，都保存最终内容（如需要）
        full_text = "".join(accumulated)
        if full_text:
            await save_final_result(full_text)

@app.get("/stream")
async def stream(prompt: str, request: Request):
    return StreamingResponse(
        generate_with_interrupt_check(prompt, request),
        media_type="text/event-stream"
    )

async def save_partial_result(text: str):
    # 保存到数据库或 Redis，标记为 interrupted
    print(f"保存中断结果：{text}")

async def save_final_result(text: str):
    print(f"保存完整结果：{text}")
```

  - 2、显式停止消息（WebSocket / 长连接）；当使用 WebSocket 时，不能简单靠连接断开（可能只是网络抖动），更清晰的做法是由前端发送一条“stop”消息
```python
from fastapi import WebSocket

async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()
    prompt = await websocket.receive_text()
    
    accumulated = []
    stop_flag = False
    
    async for chunk in fake_llm_stream(prompt):
        # 检查是否有停止消息（非阻塞读取）
        try:
            msg = await asyncio.wait_for(websocket.receive_text(), timeout=0.001)
            if msg == "stop":
                stop_flag = True
                break
        except asyncio.TimeoutError:
            pass
        
        accumulated.append(chunk)
        await websocket.send_text(chunk)
    
    # 保存结果
    result = "".join(accumulated)
    if stop_flag:
        await save_partial_result(result)
        await websocket.send_text("[INTERRUPTED]")   # 通知前端已打断
    else:
        await save_final_result(result)
```

# 2、Agent多模态输入设计

- 1、整体架构

关键就在于第二步 “模态路由/预处理”，具体策略选哪种，取决于你用的模型
```shell
用户输入（图片+文字）
       │
       ▼
┌─────────────────┐
│  输入解析器       │ ← 识别输入中是否包含多模态数据
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  模态路由/预处理  │ ← 将非文本转化为 LLM 可理解的格式
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   LLM / Agent    │ ← 接收统一的结构化消息（含图片URL或文本描述）
└────────┬────────┘
         │
         ▼
     输出动作
```

- 2、路径一 ： 原生模型支持多模态输入
```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

# 使用支持视觉的模型
llm = ChatOpenAI(model="gpt-4o")

# 构建包含图片的多模态消息
message = HumanMessage(
    content=[
        {"type": "text", "text": "请描述这张图片里的内容，并提取其中的文字。"},
        {
            "type": "image_url",
            "image_url": {"url": "https://example.com/photo.jpg"}
        }
    ]
)

response = llm.invoke([message])
print(response.content)
```

- 3、路径二：原生模型不支持多模态输入，使用工具链转换

常见转换工具

模态	转换方式

图片	--> 1. 图像描述（BLIP/CLIP） 2. OCR 提取文字  3. 目标检测、场景图生成
       
音频	--> 1. 语音识别（Whisper） 2. 音频事件分类转文本标签
       
视频	--> 1. 提取关键帧 → 图片处理 + 字幕提取
```python
from langchain.agents import AgentExecutor, create_openai_functions_agent

import base64, requests

    # 实际可调用 BLIP、Salesforce blip2 模型或 API

    """提取图片中的文字内容。"""

# 工具3：语音转文字
@tool

# 用户输入可以是一个自然语言指令，Agent 会自己规划需要调哪个工具
````
