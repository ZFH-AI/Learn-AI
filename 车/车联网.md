# 1、车联网
广义车联网包括车内网，车际网和车云网；狭义车联网专指车际网V2X，即车路云一体化协同
- 车内网：包括通过控制器局域网（CAN）或车载以太网实现汽车内部控制系统与各检测和执行部件间的数据通信
- 车云网：指车辆通过3G/4G网络实现与互联网的无线链接，如地图下载、远程诊断、车辆调度等
- 车际网：通过高可靠低时延的4G/5G无线通信技术，实现车-车、车-路、车-人之间信息互通，包括C-V2X和DSRC技术

V2V：通过车载终端进行车辆之间通信
V2N：车载终端通过无线网络与云平台通信
V2I：车载终端与路测设施通信
V2P：车与人的用户设备进行通信

```shell

    聪明的车                           |   智慧的路                                    |  可靠的网               |     强大的云

     |- V2V -- car ------------V2N UU口下发----------------> 5G基站--------------------------->| 通信网络  | ------------>  V2X业务平台、交通服务、地图服务 
     |          |                              |               |                              |          |
car -|- V2I -----------------------------> 路侧 RSU---------->MEC 路侧融合感知引擎------------->|          |
     |          |                              |               |
     |- V2P -- Person                         信号灯            路侧感知设备(摄像头、雷达)

```

# 2、车联网目标及应用场景
- 聚焦实现三大目标

   1、 提升驾驶安全：实时车车、车路、车云信息交互预警提醒，降低人为因素导致的安全事故：超视距、实时红绿灯、路况、限速等

   2、加速自动驾驶：降低单车智能成本及技术要求，使能高阶别自动驾驶：视觉盲区、博弈协同等

   3、提供交通效率：实时车路数据交互，拥堵提醒，诱导预警等错开高峰拥堵路段，提升交通通行效率：红绿灯调优，拥堵提醒，智慧公交等

- 车路协同主要应用场景

   1、城市道路：超视距路况感知、营运车辆违法治理、红绿灯信号调优、红绿灯提醒

   2、高速公路：二次事故预防、高速匝道并线事故预防、融合指挥、流量监控

   3、C-AD协同式自动驾驶：一键召车、自动停车，港口自动驾驶物流车、矿山运煤干线无人编队驾驶、无人清洁车、无人快递侧

- 2、空口资源管理

1)	5QI差异化调度

  	该功能包含基于QCI的上行预调度、SR调度，以及上下行数据信道差异化IBLER目标值。
    - 预调度是指不论UE是否向gNodeB发送SRI（Scheduling Request Indicator）请求，每隔一段时间gNodeB都会主动调度一次UE，以减少从UE发送SRI到获得上行调度授权的时间。当使用基于QCI的上行预调度时，gNodeB可以为不同的QCI承载差异化配置预调度参数组，预调度扩展应用至URLLC业务承载，达到节省调度处理时间的效果。
    - SR是上行调度的资源请求，SR周期由网络侧通过RRC信令对UE进行配置。基于QCI的SR周期可配由参数gNBDUSchParamGroup.ScheduleOptSwitch的子开关“SR_PERIOD_QCI_SW”控制。参数gNBDUSchParamGroup.SrPeriod用于配置SR周期，实现对该QCI承载的业务进行定制化的SR周期配置。当一个用户建立多个承载时，如果不同QCI承载对应了不同的QCI的SR周期配置，则按照该用户最高优先级QCI配置的SR周期参数生效。
    - 基于QCI的SR首包大小可配功能是通过对指定QCI承载配置差异化的SR首包大小，减少上行发包时延。本功能通过参数gNBDUSchParamGroup.SrSchFirstTbSize配置不同QCI承载对应的SR首包大小：当该参数配置为0（默认值）时，表示QCI承载对应的SR首包大小按照小区级SR首包大小（NRDUCellPusch.SrSchFirstTbSize）配置生效；当该参数配置为1~65535时，QCI承载对应的SR首包大小按照配置值生效。建议按照实际业务包大小进行该参数的配置。
    - 基于QCI的上、下行IBLER（Initial Block Error Rate）目标值调度，通过对基于QCI的上、下行IBLER目标值进行配置，使得对应QCI承载的业务做OLLA（Outer Loop Link Adaptation）收敛于IBLER目标值。通过配置减少IBLER目标值，从而降低误块率，减少重传次数，降低空口时延。当一个用户建立多个承载时，如果不同QCI承载对应了不同的IBLER配置，则按照该用户最高优先级QCI 配置的IBLER参数生效。

3)	控制信道资源保障

当在线用户数较多时，可能会出现高可靠CCE（Control Channel Element）不足的情况，导致高可靠用户的调度需要等待一定的时间，进而引起时延增多。同时，可以通过高可靠用户使用高PDCCH聚合级别的盲检次数，以降低PDCCH信道漏检概率。
 - PDCCH IBLER目标值优化：当配置为低时延高可靠业务时，可以配置gNBDUSchParamGroup.PdcchBlerTarget设置PDCCH误块率目标值，适量抬升PDCCH的SINR（Signal to Interference plus Noise Ratio）。对于车联业务，通过配置gNBDUSchParamGroup.PdcchBlerTarget来保障下行时延。
 - PDCCH CCE优化：当在线用户数较多时，可能会出现高可靠CCE（Control Channel Element）不足的情况，导致高可靠用户的调度需要等待一定的时间，进而引起时延增多。对于车联业务，通过配置NRDUCellPdcch.OccupiedSymbolNum、NRDUCellPdcch.PdcchAlgoSwitch的子开关“UL_DL_CCE_RATIO_ADAPT_SW”来保障下行时延。
 - PDCCH聚合级别调整机制优化：该功能通过参数gNBDUSchParamGroup.PdcchMinAggLvl控制用户配置的PDCCH最小聚合级别，在不超过最大盲检次数的情况下，提升使用高PDCCH聚合级别的盲检次数，以降低PDCCH信道漏检概率。对于车联业务，通过配置gNBDUSchParamGroup.PdcchMinAggLvl来保障下行时延。

- 3、准入与拥塞控制

  准入控制：基于ARP的用户抢占和业务抢占，在V2X用户准入失败后，V2X用户可以抢占低优先级的其他普通业务用户
 
  拥塞控制：系统拥塞时，释放低优先级GBR业务，使得接入系统的高优先级V2X业务的QoS可以得到保证

- 4、移动性管理
车联用户在道路上行驶，会在多个小区间切换。因为切换会导致调度中断，导致在小区边缘时，下行20ms@99%的满足度受到挑战，车联网重点需要避免在切换带发生乒乓切换，

常用的优化方案和手段有：

1）RF参数与功率参数优化，如通过方位角调整、下倾角调整、SSB功率偏置等参数优化保障覆盖合理性；

2）切换参数优化，如配置合理的A3切换幅度和时间迟滞。

为减少切换中断时延，3GPP R16协议规范引入了DAPS(Dual Active Protocal Stack)，即双激活协议栈，又称零毫秒切换。DAPS切换是指：在SA组网下，UE在切换过程中保持和源小区连接，当切换成功后删除源小区配置，通过先连后断的方式实现0ms切换。
 
DAPS切换是指：

UE在接收到切换请求后，继续在源小区进行数据的发送和接收。

UE同时从源小区和目标小区接收用户数据。

完成随机接入程序后，UE将上行数据传输切换到目标小区。

通过保持源小区的无线链路，DAPS减少了切换过程中的中断时间，理论上可以将用户面中断时延降至接近0毫秒。

- 5、DRX和BWP2管理

需针对V2X用户去使能终端节电相关功能，包括DRX和BWP2，避免终端因DRX休眠态、BWP2带宽不足引起数据传输时延增加。

DRX（Discontinuous Reception，非连续接收）是一种节能技术，它允许终端设备在没有数据传输时进入低功耗的休眠状态，从而减少终端功耗。

BWP（Bandwidth Part）允许终端在大带宽的系统中工作，同时只使用一部分带宽进行通信，例如：在系统初始配置时，UE可能被分配到BWP-1，其带宽为40MHz。当系统感知到UE的业务量降低时，可以通知UE切换到BWP-2，其带宽为10MHz，这种自适应的方式可以减少终端的功耗。

- 6、冗余高可靠

1)	PDCP乱序递交：如果接收端支持PDCP乱序递交，当包出现乱序时，不进行PDCP重排序，乱序递交数据包给上层处理，从而减少由于乱序导致的时延。
 
2)	双发选收

实现原理：Packet Duplication（包复制）

发送端对流进行复制发送，实现冗余；

接收端对从复制流恢复原始流中丢失数据
 
双发选收的工作原理如下：

发送端将数据包复制，然后通过两条优先级最高的链路同时发送原始包和复制包。

接收端接收到数据包后，会优先处理先到达的数据包，并将后到达的冗余数据包丢弃，以此来保证数据流的连续性和降低时延。
